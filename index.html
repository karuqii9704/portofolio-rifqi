03

Process

How a change earns the word “done.”

The same five steps sit behind every test count on this page, from the flagship builds to the smaller systems further down.

I use Claude Code every day. But traces, diffs, tests, builds, security checks, and human review decide when work ships, not the AI.

  1. 01

    Observe

    Reproduce the failure and capture the smallest trace, log, or test that shows it.

  2. 02

    Decompose

    Split analysis, frontend, backend, data, and QA work wherever running them in parallel actually helps.

  3. 03

    Implement

    Keep ownership boundaries explicit and change only what the evidence supports.

  4. 04

    Challenge

    Attack permissions, error paths, security assumptions, and regression risk before anyone else has to.

  5. 05

    Verify

    Run the tests and the build, walk the real user path, and write down what’s still uncertain.

Human integration gate

One accountable owner.

Specialist agents can chase separate questions in parallel. I reconcile what they find against the repository and own the final call. When they disagree, I go get more evidence.
